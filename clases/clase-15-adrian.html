🔑 Conceptos clave
Término Definición
REST API Interfaz que sigue los principios REST. El agente hace la llamada (pull). Verbos HTTP: GET, POST, PUT, PATCH, DELETE.
Webhook Mecanismo push inverso al REST: el sistema externo llama a tu endpoint cuando ocurre un evento. Elimina el polling y reduce latencia a milisegundos.
Evento (Event) Notificación JSON que describe algo ocurrido: session.status_idled, payment.completed. Contiene type, id y created_at.
Async vs Sync Síncrono: espera a que termine (riesgo de timeout). Asíncrono: devuelve 202 Accepted de inmediato y el trabajo va a una cola.
Autenticación Para webhooks: firma HMAC-SHA256 en X-Webhook-Signature. Para APIs: API key, Bearer JWT, OAuth 2.0. Siempre verificar antes de procesar.
Rate Limiting Límite de solicitudes por tiempo. Patrones: token bucket por agente, ventana deslizante, cuotas por costo de tokens de IA consumidos.
Retry Logic Reintento ante fallos con backoff exponencial + jitter. El jitter evita el "thundering herd problem" (avalancha de reintentos simultáneos).
Idempotencia Una operación produce el mismo resultado si se ejecuta 1 o N veces con los mismos datos. Clave para manejar reintentos de webhooks sin duplicar efectos.
Circuit Breaker Patrón que "abre el circuito" y deja de reintentar cuando un servicio está caído. Se cierra progresivamente cuando el servicio se recupera.
MCP Model Context Protocol: estándar abierto de Anthropic que estandariza cómo los agentes IA se conectan a herramientas externas. Reemplaza integraciones ad-hoc.
Dead Letter Queue Cola donde van los eventos que agotaron todos sus reintentos. Permite auditarlos, investigar el error y reprocesarlos manualmente.
ngrok Túnel HTTPS público a tu servidor local. Esencial para recibir webhooks durante el desarrollo sin necesidad de desplegar a producción.

📋 Contenido — 4 módulos
Módulo 1 · Fundamentos de integración API con agentes IA (20 min)

Los agentes IA necesitan APIs para actuar en el mundo real. Sin integración de APIs, un agente solo es un chatbot. Los 5 patrones de integración son:

1
Llamadas REST directas
El agente hace GET/POST directamente. Simple pero síncrono. Ideal para consultas con tiempo de respuesta predecible.
2
Tool Use / Function Calling
El agente decide qué herramientas usar según el contexto. El patrón más potente para agentes autónomos con Claude API.
3
MCP (Model Context Protocol)
El estándar emergente 2025-2026. Más rápido que REST ad-hoc, más fácil de depurar, estandarizado entre proveedores.
4
Plataformas unificadas
Composio, Unified.to: capa sobre cientos de APIs. El agente usa una interfaz única; la plataforma gestiona auth y traducción.
5
Protocolo A2A
Agent-to-Agent: agentes que se llaman entre sí. Arquitecturas multiagente donde un coordinador delega a agentes especializados.
Módulo 2 · Webhooks: arquitectura push y eventos asíncronos (25 min)

Regla de oro: Los webhooks devuelven el id del objeto, no el objeto completo. Siempre haz un GET adicional para obtener datos frescos. Esto evita entregar datos obsoletos en reintentos.

Comparativa Webhook vs Polling:

AspectoPollingWebhook
DirecciónTu sistema llama al externoEl externo llama a tu sistema
LatenciaMinutos u horasMilisegundos
RecursosDesperdicia CPU en llamadas vacíasSolo consume cuando hay eventos
ComplejidadSimple de implementarRequiere endpoint público + firma

Eventos de webhook de Claude Managed Agents:

EventoDescripción
session.status_run_startedEjecución del agente iniciada
session.status_idledAgente en espera de input del usuario o aprobación de herramienta
session.status_rescheduledError transitorio — reintentando automáticamente
session.status_terminatedError terminal — sesión finalizada
session.thread_createdNuevo hilo abierto en arquitectura multiagente
session.outcome_evaluation_endedEvaluación de resultado de iteración completada

@app.route("/webhook", methods=["POST"])
def webhook():
    try:
        # unwrap() verifica firma Y valida que el payload
        # no tenga más de 5 minutos (anti-replay)
        event = client.beta.webhooks.unwrap(
            request.get_data(as_text=True),
            headers=dict(request.headers),
        )
    except Exception:
        return "firma inválida", 400

    if event.data.type == "session.status_idled":
        session = client.beta.sessions.retrieve(event.data.id)
        notificar_usuario(session)

    return "", 204  # ACK inmediato

Módulo 4 · Manejo de errores, retry logic y seguridad (20 min)

Principio fundamental: Reconoce el webhook de inmediato (200 OK), luego procesa en segundo plano. Procesar síncronamente causa timeouts y falsos reintentos.

Retry con backoff exponencial + jitter:

async def llamar_con_retry(url, payload, max_intentos=5):
    for intento in range(max_intentos):
        try:
            response = await client.post(url, json=payload)
            if response.status_code == 429:
                await asyncio.sleep(int(response.headers.get("Retry-After", 60)))
                continue
            response.raise_for_status()
            return response.json()
        except Exception:
            if intento == max_intentos - 1:
                raise
            espera = (2 ** intento) * random.uniform(0.7, 1.3)
            await asyncio.sleep(min(espera, 60))  # máx 60 segundos

5 patrones de rate limiting para agentes IA:

  • Token bucket por identidad de agente — más justo que límites por IP cuando todos los agentes comparten infraestructura
  • Cuotas basadas en costo — limitar por tokens de IA consumidos, no por número de llamadas
  • Retry budget — presupuesto de reintentos por agente por unidad de tiempo
  • Circuit breaker — abre el circuito cuando la tasa de error supera el umbral
  • Throttling adaptativo — ajusta el límite dinámicamente según carga del sistema

Paso 2 — Endpoint con verificación de firma y ACK inmediato
@app.post("/webhook/lead")
async def recibir_lead(request: Request, background_tasks: BackgroundTasks):
    body = await request.body()
    firma = request.headers.get("X-Webhook-Signature", "")

    if not verificar_firma(body, firma):        # 1. Seguridad
        raise HTTPException(status_code=400)

    evento = json.loads(body)
    event_id = evento.get("id")

    if await redis.get(f"processed:{event_id}"):  # 2. Idempotencia
        return JSONResponse({"status": "ya procesado"})

    background_tasks.add_task(procesar_con_claude, evento)  # 3. ACK
    await redis.setex(f"processed:{event_id}", 86400, "1")

    return JSONResponse({"status": "recibido"})
Paso 3 — Claude procesa y clasifica el lead
async def procesar_con_claude(evento: dict):

        """}]
    )
    resultado = json.loads(response.content[0].text)
