🎯 Objetivos de la clase

  • 2 Implementar el ciclo ReAct (Reasoning + Acting) para que el agente razone antes de actuar, evalúe resultados y se autocorrija sin intervención humana en cada paso.

  • 6 Orquestar agentes multi-rol al estilo CrewAI o AutoGen, donde cada agente tiene un rol especializado y se coordinan sin necesidad de un manager centralizado externo.
🔑 Conceptos clave

Agente Autónomo (Autonomous Agent)

Sistema que percibe su entorno, toma decisiones y ejecuta acciones de manera independiente para alcanzar un objetivo, sin supervisión humana en cada paso. Mantiene estado, planifica, actúa mediante herramientas y evalúa si sus acciones lo acercan al objetivo. La autonomía no significa falta de control: el dev define los límites, las herramientas y los criterios de éxito.

ReAct Loop (Reasoning + Acting)

Paradigma central de los agentes modernos: el agente Piensa (genera razonamiento), Actúa (invoca una herramienta), Observa (recibe el resultado) y repite. La clave es que la observación alimenta el próximo pensamiento, permitiendo autocorrección en tiempo real. ReAct supera al Chain-of-Thought puro porque los resultados reales de las herramientas corrigen las suposiciones del modelo.

Planning (Planificación)

Capacidad del agente de descomponer un objetivo complejo en subpasos antes de ejecutar. Plan-and-Execute: genera el plan completo al inicio (eficiente, rígido). ReAct dinámico: re-evalúa en cada paso (robusto, adaptable). Los agentes modernos combinan ambos. LangGraph modela esta distinción explícitamente como nodos y aristas en el grafo de estado.

Tool Calling (Invocación de herramientas)

Mecanismo que permite al agente actuar en el mundo real: buscar en la web, leer/escribir archivos, consultar bases de datos, llamar APIs, ejecutar código. Claude y otros LLMs exponen tool calling nativamente: el modelo genera un JSON estructurado con nombre de herramienta y argumentos; el código Python ejecuta y devuelve el resultado como observación.

Self-Correction (Autocorrección)

Cuando una acción falla, el agente no se detiene: razona sobre el fallo, ajusta su estrategia y reintenta. Se implementa mediante el ciclo ReAct (cada error llega como Observación) + lógica de reintentos + detección de bucles infinitos (máximo N iteraciones con detección de acciones repetidas).

Orquestación sin gestor externo

LangGraph modela la orquestación como un grafo dirigido con estado compartido: los nodos son funciones Python y las aristas son condiciones lógicas, todo ejecutándose localmente. No se necesita ningún servicio SaaS externo. Esto elimina latencia de red, costos por ejecución, dependencia de proveedor y riesgos de exposición de datos.

Persistencia de Estado (Checkpointing)

Un agente sin persistencia olvida todo entre ejecuciones. LangGraph usa checkpointers nativos que guardan el estado completo del grafo en PostgreSQL o SQLite tras cada paso. Si el agente falla en el paso 7 de 10, se puede reanudar desde el checkpoint sin perder el trabajo previo.

M1 Arquitectura de agentes autónomos sin gestor externo 20 min

El problema con las plataformas gestionadas: AutoGPT Platform, LangSmith Cloud y similares cobran por ejecución, introducen latencia de red, crean dependencia de proveedor y exponen datos de negocio a terceros. Para compliance o control total de costos, la solución es la infraestructura propia.

Los tres componentes de todo agente autónomo:

  • El cerebro (LLM): Claude API o modelo local via Ollama. Recibe el contexto completo y genera la próxima acción.
  • Las manos (Tools): funciones Python que el LLM puede invocar: búsqueda web, archivos, APIs, código.
  • La memoria (State): el contexto acumulado. Sin persistencia, el agente olvida. LangGraph guarda el estado en PostgreSQL tras cada nodo.

⚡

Invoca una herramienta con argumentos concretos
👁️
OBSERVATION
Recibe el resultado real e integra al contexto
🔄
REPEAT / FINISH
¿Objetivo alcanzado? Entrega. Si no, nueva iteración
Implementación mínima — Claude API + Tool Calling (Python)
import anthropic client = anthropic.Anthropic() tools = [{ "name": "search_web", "description": "Busca información actualizada en internet", "input_schema": { "type": "object", "properties": {"query": {"type": "string"}}, "required": ["query"] } }] def run_agent(objective: str, max_iterations: int = 10): messages = [{"role": "user", "content": objective}] for i in range(max_iterations): response = client.messages.create( model="claude-opus-4-5", max_tokens=4096, tools=tools, messages=messages ) if response.stop_reason == "end_turn": return response.content[0].text # Respuesta final # Procesar tool calls → ejecutar → observación tool_uses = [b for b in response.content if b.type == "tool_use"] messages.append({"role": "assistant", "content": response.content}) tool_results = [] for t in tool_uses: result = execute_tool(t.name, t.input) # Errores → string de error tool_results.append({"type": "tool_result", "tool_use_id": t.id, "content": result}) messages.append({"role": "user", "content": tool_results})

La autocorrección ocurre naturalmente: si execute_tool lanza una excepción, el error se devuelve como Observación. Claude razona sobre el fallo y reformula la Action. Agrega un detector de bucles: si el agente invoca la misma herramienta con los mismos argumentos dos veces seguidas, está atascado.

M3 Agentes multi-step con LangGraph — De objetivo a entrega 25 min

LangGraph modela el agente como una máquina de estados explícita con StateGraph. Cada nodo es una función Python, cada arista es una condición lógica. El estado tipado fluye entre nodos y se persiste automáticamente tras cada transición.

StateGraph con persistencia PostgreSQL — sin gestor externo
from langgraph.graph import StateGraph, END from langgraph.checkpoint.postgres import PostgresSaver from typing import TypedDict, List class AgentState(TypedDict): objective: str plan: List[str] current_step: int results: List[str] final_report: str def should_continue(state: AgentState) -> str: if state["current_step"] >= len(state["plan"]): return "report" return "execute" graph = StateGraph(AgentState) graph.add_node("plan", plan_node) graph.add_node("execute", execute_node) graph.add_node("report", report_node) graph.set_entry_point("plan") graph.add_edge("plan", "execute") graph.add_conditional_edges("execute", should_continue, {"execute": "execute", "report": "report"}) graph.add_edge("report", END) # Persistencia 100% local — sin LangSmith ni ningún SaaS checkpointer = PostgresSaver.from_conn_string("postgresql://localhost/agentdb") agent = graph.compile(checkpointer=checkpointer)

Agentes multi-rol con CrewAI (autocontenido): CrewAI asigna role, goal y backstory a cada agente. La coordinación es interna al framework — ningún gestor externo necesario. Benchmark: CrewAI usa 15-20% menos tokens que alternativas en flujos secuenciales, gracias a su eficiente delegación de tareas.

FastAPI async: El agente se expone con POST /agent/run (lanza en background) y GET /agent/{id}/status (consulta estado + reporte). Un solo worker async maneja múltiples agentes concurrentes. Para mayor throughput, Aegra coordina múltiples instancias via Redis con PostgreSQL como fuente de verdad.

Observabilidad sin LangSmith: OpenTelemetry (integrado en Aegra) + Prometheus + Grafana, todos self-hosted. Cada llamada al LLM, cada tool call y cada transición de estado queda registrada localmente. Cero datos enviados a terceros.

💪 Ejercicio práctico

Construir un agente investigador autónomo de principio a fin

Objetivo: Un agente que, dado un tema, busca en la web, procesa la información, la analiza y genera un reporte en Markdown — sin intervención humana y sin ninguna plataforma externa.

Input
{"topic": "tendencias del mercado inmobiliario en Guadalajara 2026"}
Output
Archivo reporte_[topic].md con resumen ejecutivo, hallazgos, datos y fuentes
  1. Setup del entorno (10 min): pip install anthropic langgraph fastapi uvicorn psycopg2-binary · Configurar ANTHROPIC_API_KEY en .env
  2. Definir 3 herramientas (15 min): search_web(query) via DuckDuckGo API gratuita · fetch_url(url) para extraer texto limpio · write_file(name, content) para guardar el reporte
  3. Construir el grafo ReAct en LangGraph (20 min): Nodo research (ciclo ReAct: busca y recopila) · Nodo analyze (estructura hallazgos) · Nodo write (genera Markdown) · Aristas condicionales: reintentar si la información es insuficiente
  4. Wrap con FastAPI (10 min): POST /research lanza el agente en background · GET /research/{id} consulta estado y reporte generado
  5. Dockerizar y testear (15 min): docker-compose up --build · Enviar petición al endpoint · Verificar que el agente maneja automáticamente al menos un error (URL inaccesible)

Criterio de éxito: Reporte de +500 palabras con 3+ fuentes distintas, manejando errores sin intervención manual.
Variante avanzada (CrewAI): Agente Investigador + Agente Crítico (verifica fuentes, rechaza información no verificada) + Agente Redactor — 3 roles coordinados sin manager externo.
