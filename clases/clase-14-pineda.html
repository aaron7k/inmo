🎯 Objetivos de la clase
  1. Construir un asistente funcional con Claude API implementando el ciclo completo: definición de herramientas, agentic loop y manejo de tool_result.
  2. Implementar tool use / function calling con esquemas JSON reales, incluyendo llamadas paralelas y programmatic tool calling para flujos multi-paso.
  3. Crear agentes con memoria persistente usando el Memory Tool de Anthropic y patrones de contexto multi-sesión sin depender de bases de datos vectoriales.
  4. Orquestar agentes con LangGraph modelando flujos como grafos de nodos y aristas con estado compartido, persistencia y reanudación ante fallos.
  5. Comparar los ecosistemas principales (Claude API, OpenAI Assistants, LangChain/LangGraph, Flowise, Botpress) para elegir la herramienta adecuada.
  6. Desplegar un agente a producción con observabilidad básica, manejo de errores y estrategias para reducir latencia y consumo de tokens.

📋 Contenido de la clase
Módulo 1 · Fundamentos de asistentes con Claude API — 20 min
¿Chatbot vs Asistente vs Agente?

Un chatbot responde texto sin acciones externas. Un asistente mantiene contexto multi-turn y accede a herramientas definidas. Un agente planifica, ejecuta herramientas en secuencia y corrige errores en un loop autónomo hasta completar objetivos complejos.

El ciclo básico de tool use
  1. El dev define herramientas con nombre, descripción y input_schema (JSON Schema)
  2. El usuario envía mensaje con el array tools al request
  3. Claude decide si llamar una herramienta → devuelve stop_reason: "tool_use" + bloque tool_use con id, nombre y parámetros
  4. Tu código ejecuta la función con los parámetros recibidos
  5. Envías el resultado en un bloque tool_result con el tool_use_id correspondiente
  6. Claude razona sobre el resultado, repite desde el paso 3 o finaliza con end_turn
tools = [{
    "name": "buscar_propiedad",
    "description": "Busca propiedades por criterios específicos.",
    "input_schema": {
        "type": "object",
        "properties": {
            "ciudad": {"type": "string"},
            "precio_max": {"type": "number"},
            "habitaciones": {"type": "integer"}
        },
        "required": ["ciudad"]
    }
}]

response = client.messages.create(
    model="claude-opus-4-6",
    max_tokens=2048,
    tools=tools,
    messages=[{"role": "user", "content": "Busca en CDMX"}]
)
# stop_reason == "tool_use" → ejecutar y continuar el loop
Dato clave: La API es stateless — siempre envías el historial completo. Cada definición de herramienta añade ~290-675 tokens al costo según el modelo. Usa strict: true para garantizar que los parámetros sigan el schema exactamente.
Módulo 2 · Tool Use avanzado: paralelo y programático — 25 min
Parallel Tool Calling (Claude 4+)

En una sola respuesta, el modelo emite múltiples bloques tool_use simultáneos. Tu código ejecuta todas las herramientas y devuelve todos los tool_result antes de la siguiente llamada. Ideal para consultas independientes (ej.: disponibilidad en 5 ciudades al mismo tiempo).

Programmatic Tool Calling — cambio de paradigma

Claude escribe código Python que invoca herramientas en un contenedor sandboxed. Solo el resultado final regresa al contexto del modelo:

  • Procesar 20 empleados: 20 round-trips tradicionales → 1 con programmatic calling
  • Tokens reducidos hasta 10× al filtrar datos antes de llegar al modelo
  • Requiere code_execution_20260120 + "allowed_callers": ["code_execution_20260120"] en la herramienta
  • Compatible con Claude Opus/Sonnet 4.5, 4.6, 4.7, 4.8

Módulo 4 · LangGraph y despliegue a producción — 25 min
¿Por qué LangGraph?

LangGraph (v0.3, +90K estrellas en GitHub) modela flujos como grafos dirigidos permitiendo loops de razonamiento complejos, persistencia de estado entre ejecuciones, human-in-the-loop y coordinación multi-agente.

from langgraph.graph import StateGraph, END
from typing import TypedDict

class AgentState(TypedDict):
    messages: list
    herramientas_usadas: list

grafo = StateGraph(AgentState)
grafo.add_node("agente", fn_agente)
grafo.add_node("buscador", fn_buscador)
grafo.add_conditional_edges(
    "agente",
    decidir_siguiente,
    {"buscar": "buscador", "fin": END}
)
grafo.set_entry_point("agente")
app = grafo.compile()
resultado = app.invoke({"messages": [...]})

Optimización para producción
  • Prompt caching: reducir costos en system prompts repetidos (caché automático en multi-turn)
  • Container reuse: reutilizar el mismo container en programmatic calling (vida: hasta 30 días)
  • Diseño de herramientas: retornar JSON estructurado con descripción clara del formato
  • Logging: registrar todos los tool_use y tool_result para depuración
  • LangSmith: tracing completo de grafos LangGraph para identificar cuellos de botella
💪 Ejercicio práctico
🏗️ Asistente Inmobiliario con Claude API y 2+ herramientas

Objetivo: Implementar el agentic loop completo con al menos 2 herramientas funcionales y memoria entre sesiones.

Herramientas a implementar

  • buscar_propiedades
    ciudad, precio_max, habitaciones → lista de propiedades del diccionario local
  • calcular_credito
    precio, enganche_%, tasa_anual, plazo_años → mensualidad hipotecaria

Pregunta de prueba final

"¿Cuánto pagaría mensualmente por un departamento de 2 recámaras en Monterrey con presupuesto de $3M MXN, 20% de enganche y 20 años de plazo?"

El agente debe usar ambas herramientas en secuencia para responder.

def agente(pregunta):
    messages = [{"role": "user", "content": pregunta}]
    while True:
        resp = client.messages.create(
            model="claude-opus-4-6", max_tokens=2048,
            tools=tools, messages=messages
        )
        if resp.stop_reason == "end_turn":
            return resp.content[0].text
        tool_results = []
        for block in resp.content:
            if block.type == "tool_use":
                resultado = ejecutar_herramienta(block.name, block.input)
                tool_results.append({
                    "type": "tool_result",
                    "tool_use_id": block.id,
                    "content": str(resultado)
                })
        messages.append({"role": "assistant", "content": resp.content})
        messages.append({"role": "user", "content": tool_results})

Reto extra: Convertir una herramienta a programmatic tool calling con code_execution_20260120 y comparar el número de tokens usados vs. la versión tradicional.
